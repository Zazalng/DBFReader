# **RELEASING THIS PROJECT**

This project uses a GitHub Actions workflow located at **`.github/workflows/maven-publish.yml`** to publish releases to **Sonatype Central Portal** and upload Javadoc to GitHub Pages.

Publishing is **automatic**:
➡️ **Pushing a tag starting with `v` (e.g., `v1.0.0`) triggers a release.**

The workflow:

* Builds & tests on every push.
* Deploys to Sonatype when a `v*` tag is pushed.
* Generates a signed Central Portal bundle using `maven-central-publisher-maven-plugin`.
* Uploads to Central using an **Authorization: Bearer** header created from your OSSRH credentials.
* Generates GitHub Release notes.
* Builds Javadoc and deploys to GitHub Pages.

---

# **Quick Summary**

* ✔ Workflow triggers on pushing git tags `v*`
* ✔ You **must** configure OSSRH credentials + GPG key as GitHub Secrets
* ✔ No Sonatype staging repo required (new Central Portal flow)
* ✔ CI handles GPG import + settings.xml generation
* ✔ You only need to **create and push a tag**

---

# **Before releasing – Required setup**

## 1. Sonatype Central account

You must have an OSSRH account at:
[https://central.sonatype.com](https://central.sonatype.com)

Under **Account → User Tokens**, generate a User Token:

* **Token username**
* **Token password**

You will use these as secrets.

---

## 2. Required GitHub Repository Secrets

Go to:
**Settings → Secrets and variables → Actions**

Add:

| Secret name       | Description                                 |
| ----------------- | ------------------------------------------- |
| `OSSRH_USERNAME`  | Sonatype user token username                |
| `OSSRH_PASSWORD`  | Sonatype user token password                |
| `GPG_PRIVATE_KEY` | ASCII-armored private key (raw, not base64) |
| `GPG_PASSPHRASE`  | Passphrase for that key (if any)            |

> ⚠ **Workflow requires raw PGP key text**, not base64.

---

## 3. Check `pom.xml`

Your `pom.xml` must contain:

* The correct project coordinates (`groupId`, `artifactId`)
* A **release version** (no `-SNAPSHOT`)
* The `maven-central-publisher-maven-plugin` configured under the `release` profile
* Optional javadoc generation for GitHub Pages

This matches the workflow exactly.

# **Release Workflow (Recommended)**

## **1. Update the version in `pom.xml`**

Example:

```bash
mvn versions:set -DnewVersion=1.2.0 -DgenerateBackupPoms=false
```

## **2. Commit your change**

```bash
git add pom.xml
git commit -m "release: version 1.2.0"
```

## **3. Create a tag**

```bash
git tag -a v1.2.0 -m "Release v1.2.0"
```

## **4. Push commit & tag**

```bash
git push
git push origin v1.2.0
```

➡️ GitHub Actions will automatically:

1. Run tests
2. Import GPG key
3. Build the central bundle
4. Upload to Sonatype Central
5. Create a GitHub Release
6. Generate Javadoc + publish to GitHub Pages

---

# **Tag-Only Fast Release (Alternative)**

If you do **not** update `pom.xml`, the workflow still runs, but:

❗ **Artifact version will use whatever is inside `pom.xml`**, NOT the tag.

To release quickly:

```bash
git tag -a v1.2.0 -m "Release v1.2.0"
git push origin v1.2.0
```

# **Local Testing (Optional)**

You can test the release flow locally using:

```bash
mvn -P release clean verify -DskipTests
```

To fully simulate Central publishing:

```bash
mvn -P release clean deploy
```

Requires:

* Your GPG key installed locally
* `~/.m2/settings.xml` containing your OSSRH username/password

Example minimal settings:

```xml
<settings>
  <servers>
    <server>
      <id>central</id>
      <username>YOUR_USER_TOKEN_USERNAME</username>
      <password>YOUR_USER_TOKEN_PASSWORD</password>
    </server>
  </servers>
</settings>
```

# **What the GitHub Workflow Actually Does**

Your `.github/workflows/maven-publish.yml` performs:

### **Build job**

* Checkout
* Setup Java 8
* `mvn clean verify`

### **Release job**

Triggered when pushing tags starting with `v`:

* Setup Java 8 + import GPG key from secrets
* Generate `settings.xml` with Authorization header
* `mvn -P release deploy` → builds Central Portal bundle
* Upload bundle to Central with credentials
* Create GitHub Release using autogenerated notes
* Build Javadoc
* Publish Javadoc to GitHub Pages (`gh-pages` branch)

No manual Sonatype login required.

# **Common Release Problems**

### **❌ 401 Unauthorized**

Your OSSRH token is wrong or expired.
→ Generate a new token in Sonatype Central.

### **❌ GPG signing failed**

The key in `GPG_PRIVATE_KEY` doesn’t match the passphrase or has bad line endings.

### **❌ Wrong version deployed**

You tagged `v1.2.0`, but `pom.xml` says `1.1.9-SNAPSHOT`.

---

# **Security Notes**

* Never commit tokens or keys.
* Rotate any leaked credentials immediately.
* Tokens can be regenerated in Sonatype Central anytime.
* GPG private key should be dedicated for CI signing.
